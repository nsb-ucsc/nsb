Quickstart

Launch the daemon, connect a simulator, send a message, and watch it travel through NSB — all in under 10 minutes.

1
Create Configuration

Save the following as config.yaml in your working directory.

yaml
---
system:
  daemon_address: 127.0.0.1   # address where the NSB daemon runs
  daemon_port: 65432           # port the daemon listens on
  mode: 0                      # 0 = PULL (clients request messages)
  simulator_mode: 1            # 1 = Per-Node (each node has its own SimClient)

database:
  use_db: false                # false = direct transmission, no Redis needed
Field
Value
mode: 0
PULL
Clients request messages — simplest mode
simulator_mode: 1
Per-Node
Each node has its own simulator client
use_db: false
disabled
Payloads sent directly — no Redis needed
Redis is optional. For this Quickstart, use_db: false transmits payloads directly through NSB without storage. Redis can be enabled later for large-payload scenarios. Database Settings →
See all configuration fields →
2
Start the NSB Daemon

Open Terminal 1 and launch the daemon with your config file.

From the build directory:
bash
./build/nsb_daemon config.yaml
Or from the install path:
bash
/[your/install/path]/nsb/bin/nsb_daemon config.yaml
The daemon starts up and begins listening for connections. Keep this terminal open.
3
Start the Mock Simulator

Open Terminal 2. This pre-built simulator fetches payloads from NSB and passes them straight through — no real network simulator needed.

simulator.py
python
import nsb_client as nsb

# Connect to NSB as a simulator client
sim = nsb.NSBSimClient("node0", "127.0.0.1", 65432)

# Fetch the payload waiting to be simulated
entry = sim.fetch()
if entry:
    src = entry.source
    dst = entry.destination
    payload = entry.payload

    print(f"Simulating: {src} -> {dst}, payload: {payload}")

    # For this quickstart, pass straight through.
    # In a real simulator, you would route via ns-3 or OMNeT++ here.
    sim.post(src, dst, payload)
    print("Posted payload as delivered")
bash
python3 simulator.py
Start the simulator before the application so it is ready to fetch() when messages arrive.
4
Run the Application Client

Open Terminal 3. This sends a payload and waits to receive it back.

app.py
python
import nsb_client as nsb
import time

# Connect to NSB as an application client
app = nsb.NSBAppClient("node0", "127.0.0.1", 65432)

# Send a payload to "node1"
app.send("node1", b"Hello from node0!")
print("Sent payload")

# Poll for a response
time.sleep(1)
entry = app.receive()
if entry:
    print(f"Received: {entry.payload} from {entry.source}")
else:
    print("No message received")
bash
python3 app.py
Run in this order:
Terminal 1
bash
./build/nsb_daemon config.yaml
Terminal 2
bash
python3 simulator.py
Terminal 3
bash
python3 app.py

5
Two-Node Example (Python)

A complete round-trip where node0 sends to node1, and node1 replies back. This shows the full Per-Node simulator mode in action.

app_node0.py
python
import nsb_client as nsb
import time

app = nsb.NSBAppClient("node0", "127.0.0.1", 65432)
app.send("node1", b"Hello, node1!")
print("[node0] Sent message")

time.sleep(2)
entry = app.receive()
if entry:
    print(f"[node0] Received reply: {entry.payload}")
app_node1.py
python
import nsb_client as nsb
import time

app = nsb.NSBAppClient("node1", "127.0.0.1", 65432)
time.sleep(1)
entry = app.receive()
if entry:
    print(f"[node1] Received: {entry.payload}")
    app.send(entry.source, b"Hello back, node0!")
simulator.py — Per-Node, handles both nodes
python
import nsb_client as nsb
import time

sim0 = nsb.NSBSimClient("node0", "127.0.0.1", 65432)
sim1 = nsb.NSBSimClient("node1", "127.0.0.1", 65432)

for _ in range(2):
    for sim in [sim0, sim1]:
        entry = sim.fetch(timeout=0)  # non-blocking poll
        if entry:
            print(f"[sim] Routing {entry.source} -> {entry.destination}")
            time.sleep(0.1)           # simulate 100ms network delay
            sim.post(entry.source, entry.destination, entry.payload)

time.sleep(3)

You completed your first NSB co-simulation!
Here's what happened under the hood.
1
Application called send() — NSB created a SEND message and transmitted it to the daemon. The daemon queued the payload, ready for the simulator to pick up.
2
Simulator called fetch() — the daemon responded with the queued payload. In a real integration, this is where ns-3 or OMNeT++ would route the payload through a simulated network topology with configurable latency, loss, and bandwidth.
3
Simulator called post() — NSB marked the payload as delivered. The daemon queued it for the destination application client.
4
Application called receive() — NSB returned the delivered payload. That complete loop — send → fetch → post → receive — is one NSB message round-trip.
